# MiNERVA Modern アーキテクチャドキュメント

## システム全体構成

MiNERVA Modernは、フロントエンドとバックエンドを明確に分離したモダンなウェブアプリケーションアーキテクチャを採用しています。

```
                 +-------------+
                 |             |
                 |   クライアント  |
                 |  (ブラウザ)    |
                 |             |
                 +------+------+
                        |
                        | HTTPS
                        |
+-----------------------------------------------+
|               API Gateway                     |
+-----------------------------------------------+
          |                    |
          | REST API          | WebSocket
          |                    |
+---------v--------+   +-------v-------+
|                  |   |               |
|  バックエンドAPI    |   | リアルタイム   |
|  (Node.js/Express)|   | サービス       |
|                  |   |               |
+------------------+   +---------------+
          |                    |
          |                    |
+---------v--------------------v-------+
|                                      |
|            データベース               |
|           (PostgreSQL)               |
|                                      |
+--------------------------------------+
```

## データフロー

### 認証フロー
1. ユーザーがログインフォームから認証情報を送信
2. バックエンドが認証情報を検証
3. 有効な場合、JWTを発行
4. 以降のリクエストでJWTをAuthorizationヘッダーに付与

### QRコード処理フロー
1. 管理者がQRコードを生成（システムまたは手動）
2. 来場者がQRコードを受け取る
3. 会場入り口でQRコードをスキャン
4. バックエンドAPIで来場者情報を検証
5. 入場記録をデータベースに保存
6. 会場内の各ポイントでもQRコードをスキャンして追跡

### データ可視化フロー
1. 管理者がダッシュボードにアクセス
2. バックエンドAPIが集計データを提供
3. フロントエンドでデータをチャートやテーブルとして表示

## セキュリティ対策

1. **認証・認可**
   - JWTベースの認証システム
   - ロールベースのアクセス制御

2. **データ保護**
   - センシティブデータの暗号化
   - HTTPS通信の強制

3. **入力検証**
   - すべての入力データのバリデーション
   - SQLインジェクション対策

4. **API保護**
   - レート制限
   - CORS設定
